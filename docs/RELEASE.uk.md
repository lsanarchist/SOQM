# Підготовка SOQM 0.4.6

Поточна робота — оновлення джерел і локальна збірка alpha. Коміт не означає
публікацію нового інсталяційного asset, push або пройдений графічний playtest.

## Локальні перевірки

```bash
./scripts/check
python3 scripts/soqm.py verify-downloads
python3 scripts/soqm.py build
```

`./scripts/check` перевіряє структуру, локальні дані та упаковку.
`verify-downloads` потребує мережі й перевіряє **122** точні сторонні файли,
а не довільні найновіші версії. `build` створює
`dist/SOQM-0.4.6-curseforge.zip` і контрольну суму в `dist/`.
Збій завантаження означає незавершену перевірку; він не дозволяє мовчки
замінити закріплений файл.

Окремий нативний тест використовує Java 21 та ізольований світ. Після
ознайомлення й згоди з Minecraft EULA:

```bash
python3 scripts/smoke_server.py --java /path/to/java21 --accept-eula
```

Поточні адресу, порт і умови перевір у `--help` та самому harness. Звіт
`reports/smoke-server.json` має відповідати хешам поточного payload і metadata.
Його наявність або старий `passed` не означають нового успішного запуску.
Старт/reload/збереження сервера не замінюють клієнт і проходження кампанії.

## Приймання

- Установи **готовий ZIP** у чистий профіль за [інструкцією](INSTALL.uk.md).
  Перенесення файлів у MultiMC та реальний запуск перевіряй окремо.
- Пройди [графічний чекліст](PLAYTEST.uk.md). Запиши коміт, ZIP SHA-256,
  середовище, фактичні результати та відомі проблеми.
- Перевір склад пакета й походження матеріалів: без світів, акаунтів, журналів,
  кешів і сторонніх JAR, що мають надходити через manifest.
- Установи права на розповсюдження успадкованих текстів, ресурсів і модулів.
  Ліцензія репозиторію не змінює сторонні ліцензії.
- Перед комітом переглянь diff і `git diff --check`; генеровані ZIP, JAR,
  джерельні архіви, кеші та JSON-звіти залишаються локальними.

GitHub тут використовується для контролю версій. GitHub Actions не додаються.
Публікація нового asset або push — окремі дії. Історичну альфу збережено за
[незмінними посиланнями](../downloads/README.md); вона не є пакетом 0.4.6.

При майбутній публікації зафіксуй перевірений коміт, ZIP і SHA-256. У примітках
розділи виконані перевірки, джерельні історичні докази й неперевірені ділянки.
Не замінюй байти вже опублікованої версії: документація входить до ZIP, тому
навіть її зміна змінює контрольну суму. До виконання критеріїв приймання
позначай пакет як експериментальний.
