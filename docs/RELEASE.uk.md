# Підготовка релізу

Реліз має бути відтворюваним із конкретного коміту та містити точні версії залежностей. Проходження локальної перевірки не означає, що графічний клієнт або повне проходження вже перевірені.

## Локальна перевірка

У корені репозиторію виконай:

```bash
./scripts/check
python3 scripts/soqm.py verify-downloads
python3 scripts/soqm.py build
```

Окрема нативна перевірка використовує Java 21, ізольований тестовий світ і
лише `127.0.0.1:25589`. Після ознайомлення й згоди з Minecraft EULA:

```bash
python3 scripts/smoke_server.py --java /path/to/java21 --accept-eula
```

Результат — `reports/smoke-server.json`: старт, один reload, збереження і
завершення. Це не перевірка графічного клієнта чи повного проходження.

`./scripts/check` перевіряє структуру пакета й узгодженість локальних даних. `verify-downloads` окремо перевіряє закріплені зовнішні файли та потребує мережі. `build` готує архів для імпорту; поточний шлях — `dist/SOQM-0.1.0-alpha.1-curseforge.zip`. Обсяг виконаних перевірок фіксуй у примітках до релізу: локальні файли, доступність залежностей і запуск гри — різні докази.

Завантаження залежностей може не пройти через мережу, обмеження провайдера або недоступність окремого файла. У такому разі зафіксуй причину й познач перевірку як незавершену. Не замінюй закріплений файл іншим без оновлення lock-файла та повторної перевірки.

## Перевірка готового архіву

- Імпортуй **зібраний ZIP** у чистий профіль за [інструкцією встановлення](INSTALL.uk.md), а не запускай лише робочу папку розробника.
- Пройди [графічний smoke-тест](PLAYTEST.uk.md). Запиши версію, коміт, дату, ОС, Java, пам'ять і фактичний результат кожного пункту.
- Перевір склад ZIP: без світів, журналів, облікових даних, кешів, локальних шляхів і сторонніх JAR, право на включення яких не встановлено. Звичайні залежності передаються через manifest.
- Перевір походження власних і успадкованих текстів, зображень, скриптів та додаткових модів. Ліцензія репозиторію не змінює ліцензії сторонніх матеріалів. Невирішене право на розповсюдження блокує публічний реліз відповідного матеріалу.

## Публікація на GitHub

Першу альфу та її контрольну суму збережено за [посиланнями на незмінний коміт](../downloads/README.md). ZIP, `SHA256SUMS` і JSON-звіти більше не комітяться в `main`: складання створює архів і суму в `dist/`, а перевірки — локальні файли в `reports/`.

Для наступного релізу створи тег перевіреного коміту та завантаж готовий ZIP, контрольну суму й потрібні докази як вкладення GitHub Release. Онови сторінку завантаження посиланнями на ці вкладення. Не замінюй архів уже опублікованої версії: документація також входить до ZIP, тому навіть її зміна змінює SHA-256. У примітках наведи версії Minecraft/NeoForge/Java, зміни для гравця, правила перенесення світу, виконані перевірки та відомі проблеми. Не використовуй автоматичні архіви GitHub `Source code` як інсталяційний пакет.

Поки критерії alpha з [чекліста](PLAYTEST.uk.md) не виконані, позначай збірку як експериментальну й прямо вказуй неперевірені ділянки. Старі звіти бази Questing Mayhem є історичними доказами для тих файлів і версій, які вони перевіряли; новий реліз потребує власного запису перевірки.

GitHub тут використовується для контролю версій і релізів. Перевірки запускаються локально; GitHub Actions не потрібні для цього процесу.
