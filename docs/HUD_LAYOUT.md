# Розташування HUD у SOQM

У SOQM 0.4.10 клієнтський адаптер `qm-quest-ui` 0.4.3 узгоджує положення карти,
Ultimine, панелі квестів і показників спорядження. Виправлення застосовується під
час малювання HUD і працює також у вже встановлених збірках із власними
налаштуваннями FTB у каталозі `local/`.

## Що змінюється для гравця

| Елемент | Розташування та поведінка |
|---|---|
| Звичайна мінікарта Xaero | Угорі праворуч, із запасом під ефекти та стандартні сповіщення. Розмір обмежується відповідно до логічного розміру GUI. |
| Дані під картою | Їхня фактична висота враховується перед розміщенням панелі квестів. Координати та інші інформаційні рядки залишаються доступними. |
| Закріплені квести FTB | Обмежена за висотою панель під картою. Довгі рядки переносяться; список не росте за нижню межу доступного місця. |
| Ultimine | Ліворуч, нижче видимих показників кисню, енергії, RFTools і верхніх індикаторів Aether. Показується за тієї самої умови утримання клавіші, що й раніше. |
| Ad Astra | Кисень і заряд реактивного костюма поруч угорі ліворуч, зі збереженням відсотків і кольорів стану. |
| Mekanism | Заряд спорядження в лівій верхній області. Для компаса й нижнього тексту зарезервоване місце; нижні праві значки модулів підняті над шкалою Arcana. |
| RFTools Utility | Значки активних ефектів угорі ліворуч із перенесенням у наступний рядок. Власне налаштування `OFF` зберігає свою дію. |
| Jade | Зберігає бажаний якір, якщо там є місце. За потреби обходить зайняті прямокутники. Надто широкий tooltip реально масштабується разом із вмістом. |

Мапа не перекриває повідомлення `FTB Ultimine is not active`, показане на
скарзі. Режими видимості FTB, набір закріплених квестів, список незавершених
завдань та їхній прогрес беруться з нативного `PinnedQuestsTracker`.

Для прокручування закріплених квестів додані **Page Up / Page Down**. Вони діють
під час гри, коли HUD видимий і немає відкритого екрана. Клавіші можна змінити в
**Налаштування → Керування → SOQM: панель квестів**. Якщо нове стандартне
призначення вже зайняте іншою дією, адаптер залишає свою дію без клавіші;
призначення іншого мода не змінюється. `options.txt` не підміняється.

На найменшому GUI, якщо під картою не поміщається навіть один рядок із заголовком
і лічильником, залишається компактний індикатор квестів у доступному місці.
Повний список доступний у книзі квестів через кнопку в інвентарі або власне
призначення клавіші FTB Quests. Прокручування звичайної панелі переміщує її на
сторінку з одним спільним рядком, щоб зберігався контекст.

## Оновлення вже встановленої збірки

Оновити потрібно JAR адаптера разом із рештою пакета. Під час першого запуску
нової версії NeoForge створює `config/soqm-hud-client.toml` із параметром:

```toml
coordinateHud = true
```

Це діє і для старих світів, і для старих клієнтських профілів. Параметри в
`config/ftbultimine-client.snbt`, `local/ftbultimine-client.snbt`, відповідних
файлах FTB Quests та профілях Xaero не потрібно видаляти. Адаптер читає потрібні
нативні значення і коригує лише положення/масштаб під час малювання. Він не
записує файли конфігурації щокадру й не змінює збереження світу.

Щоб повернути власне розташування всіх HUD, закрий клієнт і встанови
`coordinateHud = false` у цьому файлі. Індивідуальні збережені координати та
масштаби модів знову застосовуватимуться. Власний файл адаптера не включено до
`overrides/config`, тому звичайне оновлення пакета не повинно перезаписувати
вибраний гравцем opt-out.

Причина нативного виправлення: FTB Library 2101.1.37 завантажує наявний файл із
`local/` як окремий повний override, а не зливає його з новими pack defaults.
Зміна лише стандартного SNBT не виправила б уже встановлені профілі. Крім того,
FTB Quests 2101.1.36 не обмежує висоту списку закріплених квестів і не має
нативного прокручування цієї панелі. Ці два випадки потребують адаптера.

## Масштаб GUI, масштаб карти й запас місця

Геометрія розраховується в **логічних пікселях GUI Minecraft**, після GUI Scale,
а не у фізичних пікселях монітора. Звичайна карта займає щонайбільше 32% висоти
GUI та ширину правої колонки; її нативний менший розмір зберігається. Масштаб
світу на карті, cave zoom і колесо наближення не змінюються.

Панель квестів використовує масштаб FTB у межах 0.5–0.85 та scissor-область.
Повна панель завершується над ванільними нижніми елементами, шкалою крові
EvilCraft, контекстним повідомленням Corporea, значками MekaSuit або приладами
інструментів Immersive Engineering. Компактний індикатор також враховує нижній
резерв і центральний hotbar. Tooltip Jade та підказки Ultimine можуть
зменшуватися далі, якщо вміст дуже великий.

Збільшена мапа Xaero лишається нативним тимчасовим режимом; адаптер не нав'язує
їй розміри звичайної мінікарти. Власні екрани налаштування Jade також
залишаються нативними.

## Перевірка й відомі межі

Адаптер компілюється Java 21 проти hash-pinned mapped client NeoForge 21.1.262 та
точних модів із lockfile. `build.py --verify` застосовує **справжній Sponge
Mixin 0.8.7** до 15 цільових класів цих JAR і перевіряє ін'єкції, редиректи та
аксесори. Це також перевіряє, що старі інтеграції назв предметів/JEI залишаються
в adapter JAR. Сервер не завантажує клієнтські Mixin.

Окремий probe виконує production `HudGeometry` на 320×180, 640×360 та 960×540:
три положення карти для ефектів, вузькі/широкі/дуже довгі підказки Ultimine,
список із 10 000 рядків, Jade шириною 500 px, Aether, компактний tracker і нижні
прилади. `tests/test_hud_layout.py` запускає ту саму геометрію в загальному
наборі тестів та звіряє shipped resources із JAR.

**Повний графічний клієнт Minecraft у цьому середовищі не запускався.** Native
компіляція, застосування Mixin, геометричні регресії та серверний startup не є
ігровим screenshot test. Це обмеження має залишатися в release evidence.

На мінімальному GUI неможливо одночасно гарантувати читабельність довільно
довгих tooltip, усіх можливих ефектів, кількох великих toast, великої мапи та
всіх контекстних приладів. Пошук місця використовує обмежений набір позицій;
якщо вільного прямокутника немає, зберігає видимий tooltip/індикатор. Нативні
центральні flight/radial екрани, нестандартний reversed MekaHUD і довільні
ресурспаки з іншим розміром тексту потребують візуальної перевірки в грі. Для
перевантаженого GUI допоможе менший GUI Scale або власне розташування через
opt-out; корисні HUD-функції автоматично не вимикаються.
