# Встановлення SOQM 0.4.17

Потрібні придбана Minecraft Java Edition, **Minecraft 1.21.1**, **NeoForge
21.1.262** і **Java 21**. Не оновлюй окремі моди довільно: версії та хеші
закріплено в `metadata/mods.lock.json`.

## Поточний пакет: кандидат із CI або локальна збірка

На GitHub відкрий **Actions → Validate and package** та успішний запуск для
потрібного коміту/PR. Завантаж артефакт `SOQM-candidate-<commit>` і розпакуй
зовнішній ZIP GitHub. Усередині лежать `SOQM-0.4.17-curseforge.zip` та
`SHA256SUMS`; у лаунчер імпортується саме внутрішній інсталяційний ZIP.
Артефакт доступний 14 днів, після чого його можна відтворити локально.

У корені репозиторію з Python 3.11+ та Node.js 18+ виконай:

```bash
./scripts/check
python3 scripts/soqm.py verify-downloads
python3 scripts/soqm.py build
```

Поточний результат — `dist/SOQM-0.4.17-curseforge.zip`; контрольна сума також
створюється в `dist/`. Окремий публічний asset 0.4.17 ще не заявлено. Посилання
на [першу опубліковану альфу](../downloads/README.md) веде до іншої, історичної
версії 0.1.0-alpha.1. GitHub `Source code` та вихідний Sources ZIP не є
готовими профілями для гри.
Під час збирання частини перекладів квестів об'єднуються у два мовні файли
для гри. Використовуй зібраний ZIP: копіювання `overrides/` безпосередньо
з вихідної копії не міститиме цих згенерованих перекладів.

## Новий профіль у CurseForge App

1. Вибери Minecraft → **Import** → **Import Profile .zip** → **Choose .zip file**
   та вкажи зібраний ZIP 0.4.17. Дочекайся всіх завантажень.
   [Офіційна інструкція](https://support.curseforge.com/support/solutions/articles/9000197912)
   пояснює вимоги імпорту; наявність збірки в каталозі CurseForge не потрібна.
2. Перевір Java 21 і пам'ять профілю. **6 GiB** — початкова рекомендація для
   тесту, а не виміряна системна вимога. Залиш запас для ОС та лаунчера.
3. Дочекайся головного меню, створи окремий тестовий світ і перевір книгу,
   рецепти та повторне завантаження за [чеклістом](PLAYTEST.uk.md).

Якщо мод не завантажився, перевір журнал імпорту й точну офіційну сторінку файла
з lock-файла. Не підмінюй його випадковою версією.

## Виправлення крафтів у 0.4.17

Кандидат 0.4.17 містить різні ручні сітки залізних і золотих шестерень та
мідний злиток у центрі Copper-to-Iron Furnace Upgrade. На вимкнених клієнті
й сервері онови файли `overrides/kubejs/` зі зібраного кандидата або імпортуй
повний кандидат у новий профіль. Перезапусти обидві сторони, переглянь нові
сітки в JEI та заново запиши змінені шаблони автокрафту. Усі сім шестерень
і далі потребують чотири пластини та ту саму попередню шестерню; обидва
комплекти покращення до залізної печі — вісім блоків заліза.

Пакет містить `qm-foundry-compat-0.4.15.jar` для **Modern Foundry 4.1.6**.
Модуль виправляє запис залишків інгредієнтів після забирання результату,
зокрема під час масового крафту піску в пісковик. Для наявної 0.4.14 повністю
закрий гру й сервер, додай цей JAR із `overrides/mods/` кандидата до папки
`mods/` **на клієнті та сервері**, потім перезапусти їх. Імпортований кандидат
0.4.17 уже містить модуль. Решта сторонніх модів має ті самі версії, що й 0.4.14.

Модуль навмисно вимагає Modern Foundry 4.1.6. Перед одночасним оновленням
клієнта й сервера до версії з виправленням автора, наприклад 4.1.8, прибери
цей модуль. До встановлення виправлення крафти цей рецепт у звичайному
верстаку Minecraft. Зміна Ctrl або налаштувань автозаповнення IPN не виправляє
помилковий код верстака. Дивись [причину та перевірку](CRAFTING_STATION_FIX.md)
і [контрольний тест](PLAYTEST.uk.md#верстак-modern-foundry).

## Відображення Sophisticated Storage у JEI

SOQM 0.4.17 містить `qm-storage-jei-compat-0.4.17.jar`. Він виправляє виняток
`All slots must have the same number of ingredients`, коли JEI будує компактні
рецепти покращення сховищ. Для наявного профілю 0.4.14–0.4.16 із закріпленими
модами закрий Minecraft, скопіюй цей JAR із `overrides/mods/` кандидата до
папки `mods/` **клієнта** та повністю перезапусти гру. Кожному гравцю потрібен
модуль у власному профілі. Виділеному серверу він не потрібен; сценарій
підготовки сервера SOQM його виключає.

Модуль вимагає **Sophisticated Core 1.5.14.2413**, **JEI 19.64.0.455**,
Minecraft 1.21.1 і NeoForge 21.1.262. Під час запуску Core повідомляє версію
`1.5.14`; точний архів зафіксовано у збірці. Зберігай ці залежності разом,
а перед їх узгодженим оновленням переглянь або прибери адаптер. Виправлення
пов'язує інгредієнт сховища з його фактичним слотом JEI; вартість рецепта
й перенесення вмісту сховища зберігаються. Сам цей клієнтський JAR не
встановлює попередні виправлення Foundry та рецептів майстерні. Повний
кандидат 0.4.17 містить усі три зміни.

Дивись [причину, відтворення й межі перевірки](STORAGE_JEI_FIX.md) та
[перевірки у грі](PLAYTEST.uk.md#sophisticated-storage-у-jei).

## Сортування інвентарю

Inventory Profiles Next у SOQM сортує інвентар натисканням **середньої кнопки
миші (коліщатка)**. Клавіші **R** для рецептів JEI та **U** для використання
предмета залишаються доступними. Відкрий налаштування IPN через **R+C**, щоб
змінити гарячі клавіші, блокування слотів і перенесення предметів.

Клієнтський manifest містить точні версії Inventory Profiles Next, libIPN та
Kotlin for Forge. У SOQM цей ланцюжок залежностей потрібен лише клієнту;
сценарій підготовки виділеного сервера виключає всі три моди.

## Динамічне освітлення

Клієнтський manifest містить [LambDynamicLights 4.8.11+1.21.1](https://www.curseforge.com/minecraft/mc-mods/lambdynamiclights/files/8780227).
Візьми факел або ліхтар в основну чи другу руку, щоб освітлювати простір навколо
себе. У новому профілі освітлення ввімкнено стандартними налаштуваннями мода.
Змінити його можна через **Video Settings / Налаштування графіки** або
налаштування мода у списку **Mods**; дивись
[інструкцію автора](https://lambdaurora.dev/projects/lambdynamiclights/).

Це візуальний ефект на клієнті. Для нього кожному гравцю потрібен мод у власному
профілі; на виділений сервер його встановлювати не потрібно. Офіційний JAR уже
містить потрібні бібліотеки NeoForge. SOQM зберігає твої наявні налаштування
динамічного освітлення.

## Наявний профіль MultiMC

CurseForge ZIP містить manifest та `overrides/`; це не окремий експорт профілю
MultiMC. Прямий імпорт цього ZIP у MultiMC тут не заявляється як перевірений.
Ручне встановлення потребує профілю з точними Minecraft/NeoForge/Java вище.

1. Повністю закрий гру й зроби резервну копію **всього інстансу** поза його
   папкою. Зокрема збережи `saves/`, `options.txt`, `config/`, `defaultconfigs/`,
   `local/` та дані карт, якщо вони є. Залиш оригінал для відкату.
2. Працюй із копією профілю. Розпакуй **зібраний** ZIP у тимчасову папку та
   перенеси вміст `overrides/` у його `.minecraft/`, застосувавши потрібні
   файли збірки. Не перенось туди самі `manifest.json` або GitHub source archive.
3. Установи **129** точних сторонніх JAR за manifest/lock-файлом із офіційних
   джерел; звір версії й SHA-256. Разом із **13** авторськими модулями з пакета
   це утворює набір модів SOQM. Прибери дублікати й попередні версії модів лише
   в тестовій копії; не змішуй набори різних релізів.
4. Збережи власні світи, клавіші й карти. Спочатку створи новий тестовий світ,
   потім відкрий копію потрібного світу й перевір прогрес, інвентар та рецепти.

Саме перенесення файлів не підтверджує запуск клієнта. Не відкривай вже
оновлений світ старою версією: для відкату поверни резервну копію інстансу.

## Перенесення світу

**Під час оновлення з 0.4.9 або старішої виконай [перехід сховища](STORAGE_MIGRATION.md).**
Спорожни й прибери Iron Chests у копії старого інстансу, поки цей мод іще
встановлено. Перевір розміщені контейнери, предмети, інші виміри й гравців,
які зараз не в мережі. Вилучення мода не переносить речі зі скринь.

Початкові ID квестів, задач і нагород збережено. Разом із новими уроками
HDPE та спорядження Mekanism тепер є **1642 квести, 1927 задач
і 1643 зовнішні нагороди**. Шість колишніх задач Iron Chests перевіряють
Sophisticated Storage під тими самими ID.
Старі використані нагороди не перевидаються. Назви `qm_*`
та простір імен `qm` залишаються для посилань і записаного прогресу; це не
гарантія сумісності кожного старого світу.

Перехід із 0.4.9 на 0.4.10 зберігає особисті отримання та журнал виробництва.
Вибрані дорогі крафти повертають гарантовані компоненти разом із попереднім
пакунком або кубом. Для ще не отриманої компенсації потрібен запис про справжнє
виготовлення саме цього результату поточною командою. Якщо відстеження предмета
додано лише зараз і старого доказу немає, потрібне одне нове виготовлення;
завершений квест або предмет у сховищі не імпортуються як доказ. Дивись [нагороди](REWARDS.md).

Із 0.4.8 нагороди особисті: при оновленні з давньої версії кожен має нову спробу за
вже виконані квести, де нагорода раніше була спільною. Особисті отримання,
зокрема вступна книга, не скидаються. Вихід і вступ у команду не повертає
використану особисту спробу. Старі записи спільних отримань зберігаються як історія.

Для предметів, виготовлених до появи журналу в 0.4.8, створи один новий зразок:
старі інвентарі не підтверджують виробництво. Наявні відкриття 0.4.8 збережено. Перевір рівень
через `/soqm rewards`, доступні призи — `/soqm rewards pool logistics`.
Замінюй комплект файлів повністю: старі згенеровані таблиці
`config/ftbquests/quests/reward_tables/000000006A51*.snbt` більше не використовуються;
новий каталог міститься в `kubejs/config/soqm_rewards.json`.
Завершений старий квест ME-термінала зберігає прогрес; незавершений потребує
справжнього крафту в активній мережі.
Дивись [умови міграції](CAMPAIGN_UPDATE.md#оновлення-наявного-світу).

Новий баланс луту діє при першому заповненні відповідної скрині або нового
персонального інвентарю Lootr. Уже створений вміст не очищається. Зміни шаблонів
структур діють лише для нової генерації. Для перевірки змін використовуй нові
контейнери та нові території, а не вже відкриті скрині.

Для **0.4.10 → 0.4.11** збережи світ і прогрес квестів, заміни комплект файлів
збірки та повністю перезапусти клієнт і сервер. Усі 67 завдань на відвідування
локацій звичайного світу залишаються додатковими цілями з нагородами й більше
не блокують наступні квести. Нові будинки на деревах, планетарні споруди й
підземні кімнати з'являються в нових чанках. Рукавиці Aether надягаються через
власний інвентар із кнопкою-хмаринкою, стандартна клавіша `I`; нові підказки
показують фактичне призначення клавіші. Докладніше:
[додаткові експедиції](OPTIONAL_EXPLORATION.md), [лут](EXPLORATION_LOOT.md)
та [спорядження](ACCESSORY_POLICY.md).

Для **0.4.11 → 0.4.12** заміни повний комплект файлів у копії профілю та
перезапусти клієнт і сервер. Нові рецепти діють на наступні виготовлення;
наявні машини й контейнери зберігаються. Чотирнадцять квестів MekaSuit,
MekaTool і модулів перенесено до глави 07 з тими самими ID. П'ятнадцять нових
уроків отримали окремі ID. У 29 наявних рубежах ще не отримана нагорода містить
два куби: повна кампанія дає 222 замість 193. Уже використані особисті
нагороди залишаються використаними, доплата за них не видається.
Новий клієнтський мод Quest UI потрібен для окремих іконок компенсації та
кнопки перегляду всіх можливих призів. Перегляд не отримує нагороду за гравця.
Під час ручного оновлення прибери `mods/qm-quest-ui-0.4.4.jar` із копії профілю:
там має залишитися лише новий `qm-quest-ui-0.4.5.jar` із пакета. Копіювання
нового файла поверх папки не видаляє попередню версію з іншою назвою.

Для **0.4.12 → 0.4.13** онови клієнтський профіль новим пакетом, щоб лаунчер
завантажив закріплений LambDynamicLights. Якщо встановлюєш вручну, додай точний
файл за посиланням вище до клієнтської папки `mods/` і перезапусти гру. Це
оновлення не додає серверних залежностей або окремих кроків перенесення світу.

Для **0.4.13 → 0.4.14** онови збірку та повністю перезапусти клієнт і сервер.
Під час ручного оновлення прибери `mods/qm-village-guard-0.4.2.jar` і встанови
`qm-village-guard-0.4.3.jar` із нового пакета; залиш лише одну версію.
Захист сіл тепер оновлюється за змінами цілей мобів і поселень. Наявні села
потрапляють в індекс за потреби; перетворення світу або генерація нових чанків
для цієї оптимізації не потрібні.

У звіті про проблему вкажи версію SOQM/коміт, лаунчер, ОС, Java, пам'ять і кроки
відтворення; додай `logs/latest.log` і crash report. Прибери токени, особисті дані
та приватні адреси серверів перед публікацією.
