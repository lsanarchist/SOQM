# When Dungeons Arise in SOQM 0.4.23

SOQM pins **When Dungeons Arise 2.1.68** for **Minecraft 1.21.1 / NeoForge**:
[CurseForge project 442508 / file 7150870](https://www.curseforge.com/minecraft/mc-mods/when-dungeons-arise/files/7150870).
Install the complete pack on both client and server. The exact upstream JAR is
`DungeonsArise-1.21.1-2.1.68-release.jar`; no additional mod dependency is needed.

Two narrow datapack overrides repair the upstream Fishing Hut and Thornborn
Towers advancements. Both use the existing WDA root instead of a missing
parent, and Thornborn uses the Minecraft 1.21 icon field. Their native visit
criteria, titles and descriptions remain unchanged.

## Existing worlds and pregeneration

You can keep playing an existing world. WDA's structures generate when new
chunks are created; adding the mod does not insert structures into terrain that
already exists. The [upstream FAQ](https://www.curseforge.com/minecraft/mc-mods/when-dungeons-arise)
confirms that existing worlds require new chunks for its structures.

| Terrain | Natural WDA generation after installation |
| --- | --- |
| Chunks players already visited | No retroactive structures |
| Unvisited chunks already pregenerated by Chunky or another tool | No retroactive structures |
| Chunks outside the existing generated area | Eligible for normal WDA generation |

Explore beyond the actual pregeneration boundary. A radius is relative to the
pregeneration center and chosen shape, so distance from the world spawn alone
may not identify that boundary. New terrain is eligible for generation; it does
not guarantee a structure in every chunk. A fresh world is optional.

An operator can search with a registered structure ID, for example:

```mcfunction
/locate structure dungeons_arise:illager_fort
```

A locate result is a search result, not an instruction to place a dungeon.
For existing worlds, search from new terrain and check the actual structure.
The encounter integration relies on registered structure starts and references;
a manually placed structure is not guaranteed to have those records.
SOQM does not delete regions or regenerate any part of an existing world.

## Stronger enemies inside WDA structures

`qm-dungeon-encounters-0.4.23` uses native WDA structure bounds, including
vertical bounds. It does not globally strengthen every Overworld enemy.
The default WDA enhancement chance is 100% for eligible hostiles:

| Change | Default behavior |
| --- | --- |
| Maximum health | Add 100% of the mob's base maximum-health attribute |
| Attack damage | Add 25% of its base attack-damage attribute, when present |
| Elite ability | One real Elite Mobs ability for supported `PathfinderMob` enemies |
| Apotheosis | Apply the nearby player's native world-tier augment once |

These attribute additions combine with any original WDA or world-tier bonuses;
they are not a promise to double an already modified displayed health value.
Some ranged or hardcoded attacks do not use the attack-damage attribute.
Phantoms, slimes, magma cubes and ghasts use the stat/tier path without a fake
Elite ability that their entity class cannot run. Hostile hoglins are eligible.

Native entity identity, AI, equipment, passengers, drops and custom name text
are retained. An Elite ability may add its normal label to the original name.
Passive mobs, owned pets, mimics, excluded bosses and existing Elite/Apotheosis
encounters are not given a second WDA upgrade. DivineRPG enemies keep their
separate existing policy: 12% for ordinary eligible hostiles and 85% for bosses,
in the Overworld and their own dimensions. Dimensional Dungeons remains separate.

Persistent encounter markers and fixed attribute-modifier identifiers prevent
upgrades from stacking after entity reloads. Activation near players has a
bounded per-tick budget. Structure recognition can read saved structure-start
NBT asynchronously when a large dungeon's origin chunk is unloaded; it does
not load or generate that origin chunk just to identify the encounter.

The server configuration is `config/qm_dungeon_encounters-common.toml`.
Change the existing WDA settings there to adjust its chance and stat bonuses.
A complete restart is required when updating the native module JARs.

## More accessory variety

The chest policy operates when a chest's loot is first generated. It preserves
the first copy of an original accessory with its item components and reserves
all distinct native accessory types. Additional copies of the same item ID are
replaced from a reviewed pool, without choosing a type already in that chest.

The broad pool contains **46 types: 37 Artifacts items and 9 Relics items**.
Small utility chests use a narrower utility pool. The new pool excludes
renewable-food rewards and a reviewed set of advanced or Nether/End-themed
Artifacts. Relics restricted to native End, Nether or Bastion loot are left out
of the new bonus pool. Original special drops remain protected by their existing
policy; this does not make every upstream item available through every category.

A chest with fewer than two distinct accessories may receive **at most one**
extra accessory, provided its slot and item budgets permit it:

| Chest profile | Bonus chance |
| --- | ---: |
| Settlement | 2% |
| Workshop | 4% |
| Expedition / basic dungeon | 8% |
| Stronghold / hard dungeon | 12% |
| Relic vault / dungeon vault | 16% |
| Iron Citadel supplies / treasury | 10% / 16% |
| Obsidian Abyss supplies / treasury | 12% / 16% |

This modest bonus supplements duplicate replacement. There is no global record
of a player's whole artifact collection: different chests can still contain
the same item. Duplicate replacement does not increase the number of original
accessory draws; chest budgets still limit the final loot.

The exploration policy includes 128 outer WDA chest/barrel loot-table routes.
Native special named/modelled items, keys, maps and WDA enchantments remain
protected. Trial-spawner rewards, native vault blocks, pots, archaeology and
entity drops are outside these chest routes.

Already generated inventories are not rewritten. In multiplayer, existing
personal Lootr inventories retain their items, and opening the same chest again
does not reroll its loot. A player's first new personal Lootr inventory uses
the current generation policy. See [the complete loot policy](EXPLORATION_LOOT.md)
and the item allowlist in `metadata/accessory_loot.json`.

## Installation and validation

Back up the world, stop server and clients, and install the same complete
0.4.23 package on both sides. For a manual update remove the previous
`qm-dungeon-encounters` and `qm-chest-balance` JARs before adding their 0.4.23
versions. Include the new WDA dependency, configurations, KubeJS data and
assembled quest translations. Preserve the world, player data and quest state,
then fully restart. Follow the [installation guide](INSTALL.en.md).

The native encounter and loot fixtures live in
`tests/runtime/encounter-validation/`. Fresh reports must match the actual
payload and dependency hashes; a historical report does not verify a new build.
Dedicated-server checks do not establish graphical client behavior, the natural
generation of every upstream structure or a complete survival playthrough.

## Українською

Мод працює у старому світі, але його структури з’являтимуться **лише в нових
чанках**. Якщо територію вже створив Chunky, навіть без відвідування гравцями,
потрібно вийти за межі цієї генерації. Новий світ створювати необов’язково.

Відповідні вороги всередині WDA-структур отримують +100% базового максимального
здоров’я та +25% базової шкоди. Підтримувані типи отримують одну здатність Elite
Mobs і рівень Apotheosis; для решти використовується посилення характеристик.
Наявні імена, спорядження та власний лут ворога зберігаються.

Дублікати аксесуарів в одній новій скрині замінюються різними предметами з пулу
37 Artifacts + 9 Relics. Додатковий шанс невеликий: 8% у звичайних данжах,
12% у складніших і 16% у скарбницях, якщо ліміти скрині дозволяють. Між різними
скринями повтори все ще можливі; уже відкриті скрині не перекидають лут.

Онови сервер і всі клієнти до повного пакета 0.4.23, прибери старі версії двох
авторських модулів і повністю перезапусти гру. Світ і квестовий прогрес залишаються.
Детальні кроки: [українська інструкція встановлення](INSTALL.uk.md).
