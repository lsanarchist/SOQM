# Тематичні нагороди SOQM

Звичайний квест дає **один невеликий випадковий приз зі свого тематичного пулу**. Великі рубежі залишаються помітними: 14 вибраних квестів дають по одному Mayhem Cube відповідного рівня. Книга на початку залишається особистою нагородою.

| Частина системи | Кількість |
| --- | ---: |
| Наявні зовнішні об’єкти нагород зі збереженими ID | 1626 |
| Одноразові випадкові нагороди для команди | 1611 |
| Фіксовані нагороди по одному Mayhem Cube | 14 |
| Особиста вступна книга | 1 |
| Тематичні таблиці | 14 |
| Варіанти в кожній таблиці | 5 |

Джерело складу й шансів — [`metadata/reward_pools.json`](../metadata/reward_pools.json). Воно компілюється у звичайні таблиці FTB Quests. Орієнтиром для механіки був приклад [тематичних нагород Powah у Craftoria](https://github.com/TeamAOF/Craftoria/blob/d9b70f8c6c1cdb518284287a09b59948d4960b1a/config/ftbquests/quests/reward_tables/0414572B7C36F04F.snbt); склад, кількості, бюджет і прив’язки нижче створені для SOQM.

## Що змінилося для гравця

Майстерня дає метал і паливо, склад — папір, скло та нитки, експедиції — їжу й дорожні припаси. Магічна, енергетична й космічна гілки згодом додають невеликі шанси на пляшечку досвіду або золоту моркву. У фінальному пулі є смарагд і бирка. Пізній приз містить менше одиниць, але його склад відрізняється від стартового.

Нагорода доповнює завершення задачі, а виробничий рубіж відкриває наступну частину кампанії. Звичайні призи тому не відшкодовують вартість великої машини. Для вибраних рубежів збережено окремий, відчутніший подарунок — Mayhem Cube. Випадкових машин, процесорів, HDPE, матеріалів рубежів, трофеїв босів і готового спорядження у звичайних пулах немає. Проходження не вимагає виграти певний результат.

У FTB Quests наведи курсор на нагороду: її назва показує тему, а підказка — усі п’ять результатів із шансами. Вага кожного результату дорівнює його відсотку, бо сума ваг — 100. Кількість предметів фіксована для результату; додаткового випадкового множника немає. Налаштованих порожніх результатів і автоматично доданих призів немає.

Отримання залишається ручним і одноразовим для команди. Один гравець забирає командний приз; кожен учасник отримує власну вступну книгу. Перетворення звичайної нагороди на випадкову не робить квест повторюваним.

## Повний склад пулів

«Етап» — найраніший дозволений тег `stage_N`, а не оцінка тривалості гри. Кожен рядок описує альтернативні результати **одного** отримання. Середня кількість — математичне сподівання числа предметів, а залізо враховує шматочки як 1/9 зливка. Це не загальна грошова оцінка призу.

| --- | ---: | --- | ---: | ---: |

| Запас для виробництва (`engineering`) | 1 | Редстоун ×3 — 30%; мідний зливок ×2 — 25%; залізний зливок ×1 — 20%; вугілля ×2 — 15%; скло ×3 — 10% | 2.20 | 0.200 |
| Запас енергетика (`power`) | 3 | Залізний зливок ×1 — 20%; мідний зливок ×2 — 25%; золотий зливок ×1 — 15%; редстоун ×3 — 25%; пляшечка досвіду ×1 — 15% | 1.75 | 0.200 |

Механізм вибору використовує тему глави та виправлений етап конкретного квесту. Рання задача магічної глави отримує `scholar`, доки не досягнуто етапу 2. Для інших пізніх пулів працюють ланцюжки `power → engineering → workshop`, `space → logistics` і `masterwork → power → engineering → workshop`. Перелік глав і переходів явний у політиці: нова невідома глава спричинить помилку перевірки, доки для неї не оберуть тему.

## Бюджет за частинами кампанії

Після виправлення етапів поточний маршрут дає такі очікувані суми, якщо команда завершить і забере **всі** звичайні нагороди відповідної частини. Це обчислення ваг, а не обіцянка конкретного випадкового результату. Порядок проходження та спільне накопичення ресурсів не моделюються.

| Частина | Отримань | Предметів у середньому | Залізо зі шматочками | Золота морква | Пляшечки досвіду | Бирки | Смарагди |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| Рання, етапи 0–1 | 376 | 1006.75 | 27.800 | 0 | 0 | 0 | 0 |
| Середня, етапи 2–3 | 879 | 2176.60 | 79.200 | 2.85 | 17.65 | 0 | 0 |
| Пізня, етапи 4–6 | 356 | 779.10 | 31.983 | 36.40 | 28.85 | 5.90 | 14.75 |
| **Разом** | **1611** | **3962.45** | **138.983** | **39.25** | **46.50** | **5.90** | **14.75** |

Значення в останніх чотирьох стовпцях уже входять до загальної кількості предметів. Майбутня зміна етапів може змінити розподіл між рядками; актуальний звіт друкує `campaign_refresh.py` у `rewards.stage_budgets`.

Для будь-якого звичайного отримання діють верхні межі: одна стопка з 1–4 одиниць, не більш як один зливок заліза або його еквівалент у шматочках, не більш як 0.4 очікуваного зливка. Найбільше очікуване залізо зараз у `workshop`: `0.30 × 4/9 + 0.15 × 1 = 17/60` зливка. Жодної пляшечки досвіду, золотої моркви, бирки чи смарагда у ранніх призах немає.

Конкретна виправлена помилка: три вступні задачі на залізну кирку, сокиру й меч раніше давали по 32 заліза. Тепер кожна дає стартовий приз, у якому заліза взагалі немає. Завершення цих трьох задач більше не створює виплату 96 зливків. Так само звичайні нагороди не видають пачки відер чи процесорів. Відповідні ID квестів і регресійні перевірки записано в [`tests/test_rewards.py`](../tests/test_rewards.py).

Золота морква й пляшечка досвіду є звичайними допоміжними матеріалами. Наявні рецепти не отримують обхід рубежів: для `ultimate_stew` залишаються міфічна схема й нейтронний компонент; для `xp_pump_upgrade` — попередній насос, `arcane_conduit` та `control_assembly`. Це перевірено в [`qm_expert_progression.js`](../overrides/kubejs/server_scripts/qm_expert_progression.js) і [`qm_expert_v042.js`](../overrides/kubejs/server_scripts/qm_expert_v042.js).

## Фіксовані рубежі

Кожен квест нижче дає **один** куб. Рівень куба не перевищує виправлений етап квесту. Це винагорода за пройдений рубіж або важливу подію; рутинні предметні задачі не роздають куби сотнями.

| Рубіж або подія | Рівень Mayhem Cube |
| --- | ---: |
| Промислове шасі | T1 |
| Точний механізм | T2 |
| Вимірна матриця | T3 |
| Зоряний композит | T4 |
| Міфічна схема | T5 |
| Ядро EMC | T6 |
| Контрольований перший цикл реактора | T4 |
| Керований термоядерний синтез | T5 |
| Бос Ozgum | T3 |
| Бос Rutia | T3 |
| Перша експедиція в Nether | T2 |
| Нові горизонти End | T3 |
| Розвиток спорядженої реліквії | T2 |
| Готовність до великих експедицій | T1 |

Mayhem Cube запускає окремі події. Їхні ефекти та вміст не включено до бюджетів звичайних припасів вище. Вступний опис книги нагадує відвести для кубів майданчик подалі від бази. Єдина задача статистики відкривання куба в поточній книзі потребує одного відкриття; скорочення кількості нагород не позбавляє її джерела куба.

## Сумісність з FTB Quests та збереженим прогресом

Перевірено класи `RandomReward`, `RewardTable`, `TeamData`, `QuestKey` і `BaseQuestFile` з фактично закріпленого JAR FTB Quests **2101.1.36**, а також SNBT-парсер FTB Library **2101.1.37**. Версії й SHA-256 записані в політиці нагород; ті самі залежності перелічені в [`metadata/mods.lock.json`](../metadata/mods.lock.json).

Зовнішня нагорода зберігає наявний `id`, `team_reward: true` та `auto: "disabled"`; змінюються тип і вміст. Приклад посилання на нову таблицю:

```json
{
  "id": "513013C217EF1E0B",
  "type": "random",
  "table_id": 1783693313,
  "team_reward": true,
  "auto": "disabled"
}
```

`table_id` тут — **число**, яке відповідає hex-ID `000000006A510001`. У закріпленому класі `RandomReward.readData` воно читається через `getLong`. Bare JSON-числа SNBT-парсер спочатку читає як 32-бітні `IntTag`; числове перетворення в `getLong` коректне. Для сумісності з наявними JSON-інструментами нові таблиці використовують діапазон `000000006A510001`–`000000006A51000E`. Великий 64-бітний ID без суфікса `L` цей парсер не прийме, а суфікс `L` уже не є JSON. Внутрішні ID 70 призів мають окремий стабільний простір `5A52…`.

Нативний `RandomReward` викликає один зважений вибір таблиці. Вага 0 у `RewardTable` означає автоматичне додавання призу, тому компілятор забороняє нульові ваги. `loot_size` дорівнює 1, `empty_weight` — 0, `random_bonus` — 0; підказки відкриті, використовується перекладена назва таблиці. [Нативний клас нагороди](https://github.com/FTBTeam/FTB-Quests/blob/8c53f35a97d8897c861b097f1e39f4fc3beb3a15/common/src/main/java/dev/ftb/mods/ftbquests/quest/reward/RandomReward.java) та [клас таблиці](https://github.com/FTBTeam/FTB-Quests/blob/8c53f35a97d8897c861b097f1e39f4fc3beb3a15/common/src/main/java/dev/ftb/mods/ftbquests/quest/loot/RewardTable.java) є читабельними посиланнями на відповідний upstream-код; перевірку конкретної залежності проведено окремо за її закріпленим бінарником.

Нативний ключ отриманої нагороди використовує зовнішній ID і командну/особисту область, а тип нагороди до ключа не входить. Звідси поведінка оновлення:

- Уже отриманий старий приз залишається отриманим; його ID не видає новий приз повторно.
- Завершений квест із ще не отриманою нагородою дає новий вміст після натискання отримання.
- Книга залишається особистою; її об’єкт збережено цілком.
- Наявні предмети в інвентарях і раніше видані куби не перераховуються. Оновлення не відбирає старі припаси й не повертає витрачені.

Джерела механіки ключа: [`QuestKey`](https://github.com/FTBTeam/FTB-Quests/blob/8c53f35a97d8897c861b097f1e39f4fc3beb3a15/common/src/main/java/dev/ftb/mods/ftbquests/util/QuestKey.java) і [`TeamData`](https://github.com/FTBTeam/FTB-Quests/blob/8c53f35a97d8897c861b097f1e39f4fc3beb3a15/common/src/main/java/dev/ftb/mods/ftbquests/quest/TeamData.java). Це обґрунтування сумісності за кодом; перевірку взаємодії на запущеному сервері виконують окремим runtime probe.

## Редагування та перевірка

Зміни складу слід вносити в `metadata/reward_pools.json`. Функція `campaign_rewards.apply(chapters, locale)` змінює лише наявні об’єкти нагород у пам’яті та додає українські назви таблиць. Вона викликається **після** виправлення етапів. Англійська локалізація додає `campaign_rewards.locale_entries("en_us")`. Повторне застосування не змінює вже згенерований результат.

Локальні перевірки без мережі та Minecraft:

```sh
python3 scripts/campaign_rewards.py --check
python3 -m unittest discover -s tests -p test_rewards.py -v
```

Повне відтворення після редагування політики:

```sh
python3 scripts/campaign_refresh.py
python3 scripts/localize_english.py
python3 scripts/soqm.py lock
```

Для окремого відтворення лише таблиць є `python3 scripts/campaign_rewards.py --write`. Генератор не видаляє невідомі старі ID таблиць мовчки: таке видалення потребує огляду посилань. Квести, переклади й дані гравців ця команда не записує.

Тести перевіряють незмінність усіх наявних ID і умов виконання, особисту книгу, ручне командне отримання, відсутність повторюваності, розв’язання посилань, межі етапів, точні бюджети, колізії внутрішніх ID, стабільність генерації та виправлення вступної виплати заліза. Небезпечні нові предмети, нульова вага, завелика кількість, неправильні числові ID або цикл запасних пулів зупиняють перевірку.

Серверний `scripts/runtime_probe.py` перевіряє фактичне завантаження таблиць, нативний вибір і видачу призів, повторне отримання та міграцію непорожнього прогресу. Клієнтську перевірку відкриття книги, назв пулів і відсотків у підказці слід провести в Minecraft окремо: офлайн-тести не є скриншотом інтерфейсу. Актуальні звіти повного запуску зберігаються в `reports/`.
